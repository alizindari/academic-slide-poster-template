## 3. Pre-training: the first stage of LLM training

Planned time: 0:45 to 1:45.

Start with the first stage, before assuming the audience knows what fine-tuning means. A large language model is first trained on a very large collection of text, such as books, websites and articles across many topics. ## 20. LoRA vs. Full Fine-Tuning

Planned time: 19:00 to 20:00.

Give one broad message from LoRA vs. Full Fine-Tuning: A Theoretical Perspective. Reducing the freedom of the update can improve accuracy on unseen data, beyond reducing the cost of training. The sliders are an analogy for free parameters, not actual learned values, an experiment, or a subset of editable matrix entries. Both full fine-tuning and LoRA can change every entry of the effective weight matrix. Full fine-tuning permits an unrestricted correction; LoRA imposes a low-rank structure. When the needed task change is mostly low-rank, this restriction can reduce noise fitting while retaining the useful change. If the rank is too small for the task, it can instead miss useful directions and hurt performance. The advantage depends on the task change, sample size and noise. The paper proves comparisons in linear regression and supplies supporting language-model experiments; it does not show that LoRA always wins. ## A9. Perplexity: scoring a test set

Optional appendix, outside the timed talk.

Explain the count before the formula. Each masked position is one prediction question, so the first sample supplies two scored tokens and the second supplies one. ## A14. DISeL: overhead and limitations

Optional appendix, outside the timed talk.

Three practical limitations, based on the overhead paragraph in §3 (page 4) and the limitations paragraph in §8 (page 9) of the supplied DISeL paper. First, each adapted matrix adds W_g with r d_x entries and b with r entries, or r(d_x + 1) parameters beyond LoRA at the same rank and with the same target modules. These parameters also need gradients and optimizer state during training, and the gate branch adds activations. For a square 4096-by-4096 projection at rank 16, DISeL has 196,624 trainable parameters versus LoRA's 131,072, about 1.5 times the adapter parameter count. This is not a 1.5-times total-memory or runtime claim; the frozen model still occupies memory. Second, computing gates costs O(r d_x) arithmetic per token and adapted matrix, plus sigmoid and elementwise scaling. Because G(x) depends on the input, A G(x) B cannot generally be merged into one fixed weight matrix as a standard LoRA update can. This is a structural inference cost, not a measured latency percentage; the paper does not provide a timing or peak-memory benchmark. Soft gates near zero do not by themselves skip the adapter computation. Third, retention is empirical, not guaranteed for every earlier capability. Results depend on gate initialization, learning rates, and the adapted modules. Without pre-training data in the fine-tuning loss, suppression of updates on earlier inputs is not directly enforced. The reported experiments concern single-task fine-tuning; multi-task and continual learning remain future work.
